# Little Wonders · Everyday Series web app

Static site: no server, no build step. Open `index.html`, or upload the whole folder to GitHub Pages / Netlify (all paths are relative).

- `index.html` home: sections Flashcard Packs, Games, Stories & Reading, Lessons (+ drop-down menus).
- `viewer.html?book=<id>` lesson viewer: pages as slides, games/video slots in between. ← → keys, swipe, thumbnails, full screen. `#N` in the URL jumps to step N.
- Data lives in `js/data.js` (generated by `/workspace/everyday-series/web-app-src/build_app.py`). No fetch, so the viewer works from file://.

## Offline (file://) notes
Everything now runs by double-clicking `index.html` (Chrome/Edge, no server). Tested in headless Chrome on file:// (Oct 20, 2026): home, lesson viewers, Four Corners, Land Neighbours, Story Library, Animal Memory, Match the pet, Save Sam, Jack texts, Chem Word Lab.
The fixes are applied by `web-app-src/offline_fix.py`, which `build_app.py` runs after copying the games, so a rebuild reproduces them:
- **Four Corners** (embedded copy only; Jarvis's own folders are untouched): the Vite ES-module build is re-bundled with esbuild into one classic script `assets/fc-bundle.js` (no `type=module`, no chunk preloads). Chrome blocks `fetch()` of file:// URLs and won't let file:// images into WebGL, so `assets/fc-offline.js` (only active on file://) serves every model/texture from `offline/<path>.js` script packs as Blobs. Over http(s) the normal files are used. The copied `.git` folder is no longer included.
- **Land Neighbours**: ES modules bundled into `js/app.bundle.js` (classic script). The JSON data and the WebGL/canvas images (relief map, China skins) are inlined in `js/offline-data.js`, so there is no fetch and no canvas taint.
- **Story Library**: the white-background cut-outs (kids, librarian, Hopper) are precomputed as PNGs in `assets/cut/` (same algorithm as the JS) and listed in `cutouts.js`, so there are no canvas pixel reads and no "tainted canvas" error.
- Fonts from Google Fonts need internet; without it the games fall back to system fonts.
- esbuild lives in `web-app-src/tools/node_modules` (installed with npm on first use).
- Tests: `web-app-src/tests/site-test.mjs <base-url> <tag>` (all pages) and `tests/memtest.mjs` (Animal Memory).

## Progress tracking (per student)
`js/progress.js` is one shared module (no build step) that stores each student's progress in `localStorage` (`lwp.students`, `lwp.data.<studentId>`). The default profile is **My account** (the teacher's own; id `s0`, holds all progress that existed before any student was added). It is always kept, always listed first in the dialog, and is never deleted or reset. The header shows the current profile (`Student: <name>`); click it, or the **New student** button, to open the dialog: pick any saved profile (including My account) to switch, or type a name to add a new student with a clean slate. New student only adds profiles.

Marks on home/level tiles: check mark bottom-left, counter bottom-right. Untouched items show nothing.

| type | counts as used | tile shows |
|---|---|---|
| `game` | first tap/key in a page visit = 1 play | check + play count |
| `book` | furthest page reached in the viewer (either level) | nothing below page 3; check + furthest page; check only at the last page |
| `project` | opened; finished when `data-finish` selector appears | check + infinity; check only when finished |
| `worksheet` | opened | check |
| `videoSeries` | `LWProgress.watched(seriesId, videoId)` | check + watched/total; checks per video inside the series |
| `video` | single video watched to the end | check |

**Registering new content**
- New flashcard book in `js/data.js`: nothing to do (books are `book` by default; the viewer reports pages).
- New game/page: add before `</body>`: `<script src="../../js/progress.js" data-id="games/<folder>" data-type="game"></script>` (the id is the folder path from the site root, the same path the home card links to). Use `data-type="project" data-finish=".css-selector-of-end-screen"` for open-ended projects, `data-type="worksheet"` for one-offs.
- New video series: add `'<folder id>':{type:'videoSeries',total:N}` to `REG` at the top of `js/progress.js`, load the script on the series page, call `LWProgress.watched('<folder id>','<video id>')` when a video ends, and use `LWProgress.isWatched(...)`/`LWProgress.checkHTML()` to mark the list.
- To override a type without touching the page, add it to `REG` in `js/progress.js` (e.g. `'chem':{type:'worksheet'}`). Items not listed default to `book` (ids without a slash) or `game`.
- Video lessons section: `js/app.js` moves Everyday English (Max), comic stories and Conversations into "Video lessons" (`VIDEO` map / `group==="Conversations"`). Rebuild safety: `web-app-src/progress.js` is the source of `js/progress.js`, and `web-app-src/progress_apply.py` (run by `build_app.py` after `offline_fix`) re-inserts the progress script tags and hooks into the copied pages, so a rebuild keeps progress tracking and My account. (`web-app-src/app.js`, `index.html`, `viewer.html` carry the hooks directly; they predate later hand edits in the repo, such as book.html, Alphabet Games and the Video lessons menu, which a rebuild would still drop.)

## Goals, points and the gold coin star

The header shows a gold coin star next to the student name. It opens a dropdown with the six goals shown to parents (Words I know, Spelling and letters, Making sentences, Grammar, Listening and understanding, Talking about my world). Each goal shows the student's level (A1, A2 or B1), a progress bar and a status word, and expands into a plain-language breakdown ("Weather: 2 of 12 word cards seen", "Letter sequence: first success at level 2, improved to level 3"). The level is chosen automatically (the highest level with 10 or more points) and can be set by hand in the dropdown.

**Scoring is hidden and per student.** Points go only to a first completion and to an improvement. Repeating something earns nothing.

| Event | Points | Where it is recorded |
|---|---|---|
| Book page coin (first time per page) | 1 x the page type weight (word card, bridge, pairs, story page, worksheet; "other" pages 0.3) | `LWProgress.coin(book, page)` |
| First play of a game | 1 | `LWProgress.played` (automatic) |
| First success of a named task (`win`) | 3 | `LWProgress.win(id, key, {v})` |
| Improvement of that task (higher `v`) | 1.5 each, up to 3 improvements | same call, later with a higher `v` |
| Video or video series item finished | 4 | `LWProgress.watched` (automatic) |
| Worksheet or project finished | 2 | `LWProgress.finish` (automatic) |
| Correct choice (each distinct choice once, cap 12 per item) | 0.75 | `LWProgress.correct(id, key)` |

Raw events are stored in `localStorage` under `lwp.goals.<student id>`. Points are **computed when the dropdown opens** from those raw events and the registry, so changing a tag re-scores history. One goal bar fills at 30 points per level.

### The tag registry (how future content joins the system)

- `js/goal-tags.js` (hand-edited) holds the six goals with their A1, A2 and B1 wording, the grammar point list, the topics (weather, actions, chores, family), the page-type weights, and `ITEMS`: one entry per game, lesson, video series, worksheet set or book that is not an Everyday book. An entry declares its level (`lvl`), which goal bars it feeds (`bars`, weights are normalised), optional `topic`, grammar (`g`), named wins (`wins`), and totals used in the "x of N" lines.
- `js/goal-books.js` (generated, do not edit) tags every page of every Everyday book with its page type, grammar points and topics. It comes from `tools/goal-book-source.json`; run `python3 tools/gen_goal_books.py` after changing that file. The grammar and topic tags were produced by a heuristic (patterns plus a word list, estimated 90 to 95 percent right) and spot-checked by hand.
- `js/goals.js` is the engine and UI (loaded automatically by `progress.js` on pages that have the site header).

**To add new content:** give it a stable id (its path, e.g. `games/my-game`), add one `ITEMS` entry in `goal-tags.js`, and make the page report what happened. A game that is only played needs nothing more, because the first tap is recorded. For wins call `LWProgress.win('games/my-game','round',{v:levelReached})` when a task is first completed and again with a higher `v` when the child improves. Repeats are ignored automatically. Content that has no entry is still scored, with a default for its type, and its id is logged to the browser console as "content without a tag entry". A new Everyday book needs no code: add it to `tools/goal-book-source.json` (level, family, per-page type, grammar, topics), regenerate `goal-books.js`, and every page gets its coin.

### Book page coins

Every page in `viewer.html` carries a small gold coin in its top right corner. A coin is collected only after the page was really on screen (at least a quarter of it visible) and the coin has scrolled up to the header. Jumping straight to a later page does not collect the pages skipped. The coin then slides into the header star with a soft chime made with WebAudio (no sound file), and the star pulses. Each page pays once per student. The dropdown has a Coin sound switch (`localStorage lwp.coinsound`). `prefers-reduced-motion` shortens the animation.

### Rebuilds

`web-app-src/progress_apply.py` copies `progress.js`, `goals.js`, `goal-tags.js` and `goal-books.js` and re-applies the small `LWProgress.win/correct` hooks in the game pages (`GOAL_RULES`), so a rebuild keeps all of this.
## Teacher's Corner (blackboard)
An icon-only **Teacher's Corner** button (aria-label and tooltip keep the name) sits inside each page's own top row or header, styled like the buttons beside it. It is never a floating overlay. It opens a full-screen blackboard: pure-CSS wood frame, green slate, chalk toolbar and chalk stage, matching the one in Four Corners. Close it with the Close button or Escape (Escape closes the innermost layer first: text box, then note card, then the board). It shows and hides instantly, has no sounds, and only the Listen button on a note card speaks (browser speech).

- Tools: chalk, highlighter, eraser, line, arrow, rectangle, circle, text; four chalk colours plus a colour picker; chalk size; undo, redo, clear (Ctrl/Cmd+Z, Ctrl+Y also work); Add picture (button or drop an image on the board); Save as image (PNG); full screen. The drawing stays in memory until the page is reloaded.
- Notes list (left side, instead of the Four Corners Lessons list): the how-to for the current page or book, built from data already on the page. On a book page: About this book, How to use it, Book note, Goals for this book and Goals for page N (when `LWGoalBooks` exists). Home page: how to use the site and Student progress. Every page also has **My notes**, a free text box kept on this device per page.
- Badge: shown only when there is something meaningful, namely authored notes not opened yet (a book note, goals, or notes a page supplies). It is hidden at 0 and counts per student. Add page notes with `window.LWTeacherNotes=[{id:'warm',title:'Warm-up',text:'Line one.\n- bullet'}]`.
- Files: `js/teachers-corner.js` and `css/teachers-corner.css` (the script loads the CSS and fonts itself). Add `<script src="../../js/teachers-corner.js"></script>` before `</body>` on any new page (path relative to the page), and put `<span data-tc-slot></span>` in the page's top button row. Optional: `data-tc-class="btn-class"` makes the button wear a host class, and `--tcs-size`, `--tcs-radius`, `--tcs-bg`, `--tcs-bg-hover`, `--tcs-color`, `--tcs-border`, `--tcs-shadow`, `--tcs-icon` on the slot match the host look. Without a slot the button falls back to the site header, then to a normal in-flow row at the top of the page. Four Corners has its own built-in Teacher's Corner, so it does not load this one.
- Rebuild safety: `web-app-src/teachers-corner.js`, `teachers-corner.css` and `teachers_corner_apply.py` (run by `build_app.py` after `progress_apply`) re-copy the two files and re-insert the script tag in every page, so a rebuild keeps the Teacher's Corner.
